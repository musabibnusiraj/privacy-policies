Privacy Policy for Masjid Prayer Display SriLanka

Last updated: 5 October 2026

App: Masjid Prayer Display SriLanka · Developer: Aimzcode · Package: dev.aimzcode.successcall

Thank you for choosing Masjid Prayer Display SriLanka (“we,” “us,” “our”), developed by Aimzcode. This Privacy Policy explains what information the app handles, why, and what leaves your device. It applies to the Google Play listing published under the package name dev.aimzcode.successcall, used on Android phones, tablets, Android TV / Google TV devices and HDMI display boxes installed in masjid halls.

In short: Masjid Prayer Display SriLanka has no user accounts you sign into, no advertising and no analytics or tracking SDKs. It never accesses your device's location. To let a masjid's prayer settings sync across the devices showing that masjid's display, the app stores the masjid's prayer configuration (not personal data about you) in a cloud database, using an anonymous, unidentifiable device credential.

Information We Collect

We do not collect personal information about you

The app has no sign-up, login, profile or messaging feature. We never ask for your name, email address, phone number or date of birth, and nothing you type into the app is used to identify you personally.

We do not access your location

Masjid Prayer Display SriLanka does not request, access or use your device's GPS or location services.

  • Prayer times are calculated from a district/zone you select manually from predefined areas in Sri Lanka, not from GPS.

Information stored only on your device

Your display's settings are saved in local app storage on the device itself:

  • Selected prayer zone, district and data source
  • Iqamah offsets and prayer-time adjustments
  • Weekly adhan overrides and test-time settings
  • Display preferences (theme, language, clock style, Hijri date, neumorphic/analog clock options, what's shown on screen)
  • A cached copy of prayer times and Hijri calendar data, so the display keeps working offline
  • An internal masjid record code generated when you set up the display

This data stays on the device. Uninstalling the app, or using Reset App in Settings, deletes it from that device.

Masjid configuration stored in the cloud (so multiple displays stay in sync)

When you set up a display for a masjid (the one-time onboarding screen), the app creates a record for that masjid in our cloud database (Google Firebase/Firestore) so that:

  • The same masjid's prayer settings can be shared across several display devices installed in the same hall, or restored if a display is replaced.

That masjid record contains only the configuration you enter for the display, never anything that identifies you personally:

  • Masjid name, zone and district you entered
  • An internal masjid record code
  • Iqamah times and prayer-schedule adjustments for that masjid
  • The display's app settings (language, theme, clock style, what's shown on screen, and similar preferences) — so another display for the same masjid shows the same setup

We do not collect your name, contact details, precise location, or anything about how you personally use the app in this record — only the masjid's prayer-display configuration.

Anonymous device credential (Firebase Authentication)

To control which device may create or update a masjid's record, the app signs the device in to Firebase Authentication anonymously. This creates a random identifier for the installation — it is not a username, email or phone number, is not linked to your real identity, and you are never asked to provide any credential yourself. It exists purely so our database rules can tell “a device that set this masjid up” from “an unrelated device,” so a masjid's settings cannot be edited by someone who did not configure that display.

Information That Leaves Your Device

The app is not fully offline. The following things involve a network connection.

1. Prayer-time and Hijri calendar data

The app downloads prayer times and Hijri calendar data from our static hosting on GitHub Pages (successcall.github.io). These are plain file downloads — the app sends no personal data. As with any website, the hosting provider (GitHub) automatically processes your IP address in its standard server logs to deliver the file. We do not receive, store or have access to those logs.

2. Masjid configuration sync (Google Firebase / Firestore)

As described above, the masjid name, zone, district, iqamah times, prayer-schedule adjustments and display settings you configure are saved to Google Cloud Firestore, associated with an anonymous Firebase Authentication credential for the device — not with you personally. Google's handling of this data is governed by Google's Privacy Policy.

We do not use Firebase Analytics, Crashlytics, advertising, or any other tracking or profiling service.

3. App updates

The app checks a small version file on our GitHub Pages hosting, and uses Android's in-app update API (Google Play) to check whether a newer version of the app is available. No personal data is sent beyond the standard request information (such as your IP address) that any network request involves.

Permissions

This is a display app meant to run continuously on a screen in a masjid hall. Only the permissions below are ever requested:

The app is built for Android phones/tablets, Android TV, Google TV and Android-based HDMI display boxes; it is excluded on Google Play from phone-class devices that do not fit a masjid-display use case, through Play Console device targeting rather than a runtime check.

Children's Privacy

Masjid Prayer Display SriLanka is suitable for all ages. We do not knowingly collect personal information from anyone, including children under 13. There are no accounts, chat, or user-generated content shared with other people.

Data Security and Retention

  • Device-local preferences and cached prayer data are stored in the device's app-private storage, protected by the operating system.
  • Masjid configuration records in Firestore are protected by database rules that only allow the device that created a masjid's record (identified by its anonymous credential) to update or delete it; anyone can read a masjid's current display settings by its record code (so the display can show them), but the full list of masjid records cannot be browsed.
  • Uninstalling the app removes all locally stored data from that device. To have a masjid's cloud record removed entirely, contact us using the details below with the masjid name and record code.

Your Choices

  • Use the app without cloud sync. The display works from its local cache even if the cloud sync step fails or is unavailable; cloud sync only matters if you want several displays to share one masjid's settings.
  • Reset the device's local settings at any time using Reset App in Settings.
  • Request deletion of a masjid's cloud record by contacting us with the masjid name and record code.
